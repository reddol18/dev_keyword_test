# 플레이 스토어 첫 출시 기록

> 2026-11-17 · 용어먹는하마 `io.github.reddol18.wordbook` · 버전 1.0.0 (버전 코드 2)
>
> **실제로 지나온 과정의 기록이다. 안내서가 아니다.** 콘솔 화면을 캡처로
> 확인하면서 한 단계씩 진행했다. 각 단계마다 근거를 표시했다.
>
> - **확인됨**: 콘솔 캡처나 코드·빌드 결과로 직접 확인한 것
> - **미확인**: 사용자가 캡처 없이 진행해서 실제 입력값을 보지 못한 것
>
> 콘솔 화면은 자주 바뀐다. 다음 출시 때는 이 문서를 정답으로 쓰지 말고,
> **화면을 보면서 대조하는 용도로** 쓴다.

## 진행 순서

### 1. 대시보드 할 일 목록 — 앱 설정

앱을 만든 직후 대시보드에 `앱 설정` 할 일이 나온다. 메뉴를 찾아 들어갈
필요 없이 **목록 항목을 바로 누르면 된다.** (확인됨, 캡처)

이때 `앱 출시` 쪽 트랙은 전부 자물쇠로 잠겨 있고 **내부 테스트만 열려 있다.**

| 항목 | 입력값 | 근거 |
|---|---|---|
| 개인정보처리방침 설정 | `https://reddol18.pe.kr/privacy/yongeo-hama.html` | 확인됨 (게시 개요). URL 접속과 AdMob·광고 ID 언급도 확인 |
| 로그인 세부정보 | 특수한 액세스 권한 없이 모든 기능 사용 가능 | 확인됨 (게시 개요) |
| 광고 | 광고 포함 | 확인됨 (게시 개요에 "광고 선언 업데이트") |
| 콘텐츠 등급 | 설문 제출 | 제출은 확인됨. **설문 답변은 미확인** |
| 타겟층 | 만 18세 이상 | 확인됨 (게시 개요) |
| 데이터 보안 | 설문 작성 | 작성은 확인됨. **유형별 답변은 미확인** |
| 정부 앱 · 금융 기능 · 건강 | 해당 없음 | 선언 완료는 확인됨 |
| 판매자 상태 | §2 참조 | 확인됨 |
| 앱 카테고리 · 연락처 | §3 참조 | |
| 스토어 등록정보 | §4 참조 | |

**콘텐츠 등급과 데이터 보안에서 사용자가 "가이드가 틀렸다"고 지적했다.**
어느 항목이 어떻게 달랐는지는 기록하지 못했다. 다음에 이 두 화면은
반드시 캡처를 보면서 답한다.

데이터 보안 답의 근거로 쓴 코드 사실 (확인됨):
- 앱 자체는 네트워크 통신이 없다. `fetch`·`axios` 호출이 없다
- 학습 기록은 `AsyncStorage` — 기기에만 저장된다
- 데이터를 모으는 것은 AdMob SDK 뿐이다
- 릴리스 APK 매니페스트에 `com.google.android.gms.permission.AD_ID` 가 머지돼 있다 (`aapt2 dump permissions`)

### 2. 앱 콘텐츠 — 주의 필요 3개

앱 설정을 다 하면 `앱 콘텐츠` 화면에 `주의 필요(3개)` 가 따로 뜬다.

| 항목 | 입력값 | 근거 |
|---|---|---|
| 광고 ID | **예** · 목적은 **광고 또는 마케팅 하나만** | 확인됨 (캡처) |
| 건강 앱 | 해당 없음 | 완료 확인됨 |
| 앱 수준 판매자 상태 및 서비스 약관 | **예, 이 앱에 판매자 상태가 적용됨** (기본값 유지) · 서비스 약관 URL **비움** | 확인됨 (캡처) |

- 광고 ID 화면의 `애널리틱스` 는 체크하지 않는다. 화면 설명상 앱이 직접 쓰는
  분석 도구(Firebase 등)를 뜻하고, AdMob 광고 실적 측정은 `광고 또는 마케팅`
  설명에 포함돼 있다.
- 판매자 상태를 `아니요` 로 하면 EU·영국 사용자에게 "소비자 보호법이 적용되지
  않는다"고 안내된다. 광고 수익이 있으므로 `예` 가 맞다.
- 서비스 약관은 "가능한 경우" 입력하는 선택 항목이다. 개인정보처리방침 URL 을
  넣으면 안 된다 (다른 문서다).

### 3. 스토어 설정

| 항목 | 입력값 | 근거 |
|---|---|---|
| 앱 또는 게임 | 앱 | 확인됨 (캡처) |
| 카테고리 | 교육 | 확인됨 (캡처, 게시 개요) |
| 태그 | 권한 것: `시험 준비` · `채용 면접` · `교육` · `학습 가이드` | **실제 선택은 미확인** |
| 연락처 | 이메일 · 웹사이트 | **입력값 미확인** |
| 외부 마케팅 | 체크 유지 (기본값) | 확인됨 (캡처) |

태그는 콘솔이 주는 목록에서만 고른다 (최대 5개). 목록 전체를 받아 보고 골랐다.
- 앱의 목적이 **IT 면접 준비**라서 `채용 면접`·`시험 준비` 를 넣었다
- `언어 교육`·`문법`·`발음` 은 뺐다. 관련 태그가 `언어 교육` 이라 영어 학습
  앱들과 비교 그룹이 묶인다
- 목록에 `교육 > 학습` 같은 항목은 **없다**

### 4. 기본 스토어 등록정보

`① 애셋 → ② 리뷰` 두 단계다. `*` 가 붙은 섹션만 필수다.

| 항목 | 값 | 근거 |
|---|---|---|
| 앱 이름 | `용어먹는하마` (6/30) | 확인됨 |
| 간단한 설명 | `store/listing-ko.md` | |
| 자세한 설명 | `store/listing-ko.md` (사실 오류 3곳 고친 판) | 문안을 코드와 대조함 |
| 앱 아이콘 | `store/icon-512.png` — 512×512, 562KB (한도 1MB) | |
| 그래픽 이미지 | `store/feature-graphic.png` — 1024×500, 24비트 | |
| 휴대전화 스크린샷 | `store/screenshots/` 5장 — **1080×1920** | 확인됨 (캡처) |
| 동영상 · 태블릿 · 데스크톱 · XR | 비움 (`*` 없음) | |

**스크린샷 비율 — 처음 만든 파일이 조건에 안 맞았다.**
- 화면 조건: **가로세로 비율 16:9 또는 9:16**
- 갤럭시 S8 원본은 1080×2220 (약 9:18.5). 긴 변이 짧은 변의 2배를 넘는다
- 상태 표시줄(위 72px)과 내비게이션 바(아래 144px)를 잘라 **1080×1920** 으로
  맞췄다. 화면마다 내용이 잘리지 않게 자르는 위치를 따로 정했다
- 업로드하면 순서가 섞여 들어온다. **올린 뒤 직접 끌어서 순서를 맞췄다**

**자세한 설명 — 예전 문안의 사실 오류 3곳 (코드와 대조해 고침)**
- 오답노트를 펼치면 "분야와 난이도"가 보인다 → 실제로는 `뜻·인정 표기·비슷한 말·헷갈리는 것`
- 영단어 덱은 "보기를 고르는 대신" 직접 쓴다 → 객관식도 있다
- `kind`·`careful` 예시 → 쓰이지 않는 옛 `words.json` 의 단어였다. 실제 덱의 `deprecated`·`implicit` 로 교체

저장하면 `기본 스토어 등록정보` 상태가 `검토를 위해 전송 준비 완료` 가 된다.

### 5. 프로덕션 버전

앱 설정을 다 마치면 대시보드의 트랙 자물쇠가 모두 풀린다. **프로덕션도 열려
있었고 `프로덕션 신청`(테스터 12명·14일 요건) 항목은 없었다.** (확인됨, 캡처)

| 단계 | 값 | 근거 |
|---|---|---|
| 국가/지역 | 대한민국 1개 | 확인됨 (게시 개요) |
| App Bundle | `android/app/build/outputs/bundle/release/app-release.aab` | |
| 출시명 | `1.0.0 첫 출시` | 확인됨 (게시 개요) |
| 출시 노트 | `<ko-KR>` 태그 안에 작성 | |

**막힌 곳 두 개**

**① 오류: "앱이 16KB 메모리 페이지 크기를 지원하지 않습니다"** — 저장 불가
- AAB 안의 64비트 `.so` 17개를 ELF `PT_LOAD` 정렬로 검사했더니 `libonnxruntimejsi.so` 하나만 4KB
- 이 라이브러리만 `onnxruntime-react-native` 의 `CMakeLists.txt` 로 우리 빌드에서 컴파일된다. NDK r27b 의 기본 정렬이 4KB 다
- `scripts-postinstall.js` 에 `-Wl,-z,max-page-size=16384` 링커 옵션 패치를 추가 → 재빌드 후 17개 모두 16KB
- `무시하고 계속하기` 는 쓰지 않았다. 16KB 페이지 기기에서 앱이 시작 즉시 죽을 수 있다
- 검사 스크립트: 세션 스크래치패드의 `elf16k.mjs` (보존 안 됨, 필요하면 다시 쓴다)

**② 오류: 버전 코드 1 이 이미 사용됨**
- 16KB 오류가 난 첫 AAB 가 업로드되면서 버전 코드 1 을 차지했다. 출시하지 않고 지워도 재사용 불가
- `app.json` 의 `android.versionCode` 와 `android/app/build.gradle` 을 2 로 올려 재빌드
  (`android/` 는 prebuild 가 다시 만드므로 `app.json` 에도 넣어야 유지된다)
- **처음 AAB 를 교체할 때 미리 올렸어야 했다.** 알고도 안 해서 업로드를 한 번 더 했다

**경고 (무시함)**: "가독화 파일 없음" — 비정상 종료 기록을 읽기 쉽게 하는 보조 파일. 출시를 막지 않는다.

### 6. 게시 개요 → 제출

`게시 개요` 에 변경사항 11개가 모인다. 각 행을 입력값과 대조한 뒤
`검토를 위해 변경사항 11개 제출`. 빠른 검사(최대 14분)가 도는 중에 제출해도
검사가 끝나면 자동으로 넘어간다. 제출 후 상태는 `검토 중인 변경사항`.

## 이번에 틀렸던 것 — 다음 진행 방식에 반영할 것

| 틀린 것 | 원인 |
|---|---|
| 메뉴 경로를 "앱 콘텐츠 → 데이터 보안" 식으로 안내 | 화면을 보기 전에 기억으로 말함. 실제로는 대시보드 할 일 목록을 누르면 된다 |
| 태그 "교육 > 학습" | 목록을 보기 전에 추측. 그런 항목은 없다 |
| 테스터 12명·14일 요건이 걸린다고 안내 | 이 계정의 대시보드에는 해당 요건이 없었다 |
| 광고 ID 목적에 "애널리틱스" 포함 | 화면 설명을 읽기 전에 답함 |
| 스크린샷을 1080×2220 으로 준비 | 화면 조건(9:16)을 대조하지 않음. 내 문서에 "2배 이내" 조건을 써 놓고도 놓침 |
| 등록정보 문안에 사실 오류 3곳 | 예전에 쓴 문안을 코드와 대조하지 않고 넘김 |
| 버전 코드를 미리 안 올림 | 위험을 알고도 "나면 대응"으로 미룸 |
| 끝난 일을 반복해서 물음 | 이미 받은 답(키스토어 백업)을 기억하지 않음 |

**공통 원인: 화면이나 코드를 확인하기 전에 답했다.**
진행 방식은 **화면 캡처 → 그 화면의 항목 하나 → 입력값과 근거 → 다음 캡처** 로 한다.
사용자가 직접 입력하는 단계에서는 다음 단계를 미리 말하지 않는다.
